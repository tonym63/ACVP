=== Required Prerequisite Algorithms for X-WING Validations

X-WING relies on underlying cryptographic primitives as defined by the X-WING specifications.  Each prerequisite algorithm required for X-WING validation *MUST* be validated either separately or as part of the same submission.  ACVP provides the prereqVals mechanism for specifying the applicable prerequisite algorithm validation.

The implementation relies on the following underlying algorithms:

   * ML-KEM-768: Conforming to FIPS 203 <<FIPS203>> (Module-Lattice-Based Key Encapsulation mechanism)
   * X25519: Conforming to SP 800-186 / RFC7748 for elliptic-curve cryptography<<RFC7748>>.   
   * X25519:as specified in <<RFC7748>>, is a required prerequisite algorithm for X-WING validation.

=== Prerequisite Validations

Before X-WING algorithm validation can be executed, the underlying cryptographic libraries must demonstrate successful validation of the following prerequisite algorithm primitives:

.Prerequisite algorithm primitives
|===

| Prerequisite Primitive | Standard Reference | Operational Purpose

| SHA3-256 / SHAKE256

| FIPS202

| Message hashing and internal domain separation matrix generation within ML-KEM.

| KDF (HKDF-SHA256)

| SP 800-56C

| Hybrid key derivation and combination layer for component secrets.

|===

=== ACVP Validation Interface & JSON Profile

The validation process uses standard ACVP JSON profiles to communicate registration data, test vectors, and response structures.

=== X-WING Algorithm Registration Properties

Each X-WING algorithm capability advertised is a self-contained JSON object using the following values.

.X-WING Algorithm Capabilities JSON Values
|===
| JSON Value | Description | JSON Type | Valid Values
| algorithm | Algorithm Validation | string | X-WING
| mode | X-WING mode to be validated| string | keyGen, encapDecap                             
| revision | The algorithm testing revision to be used | string | See <<supported>>
|prereqVals | Prerequisite algorithm validation | array | See <<prerequisites>>
| function | The X-WING operation supported by the IUT | array | encapsulation, decapsulation
|===

Note: The function property is applicable only to X-WING/ encapDecap registration.

=== Algorithm Registration Capabilities

THe following JSON payload outlines the capabilities registration block sent by the client to request X-WING test vector challenges:

.Registration Block Schema
[source,json]
----
{
  "acvVersion":"1.1.0",    
  "algorithms": [
   {
    "id": 0,
    "algorithm": "XWING",
     "revision": "1.0",
     "capabilities": [
     {
       "mode": "keyGen",
        "role": ["initiator","responder"]
      },
      {
        "mode":"encapsulation",
         "role":["initiator"]
       },
       {
         "mode":"decapsulation",
          "role":["responder"]
        }
       ]
      }
    ]
 }
----
